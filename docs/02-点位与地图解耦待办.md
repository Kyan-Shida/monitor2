## 1. 背景

PRD（`机器人平台PRD-V1.0.1.md` 第 17 条）已定稿：

> 点位只存坐标，不绑地图；地图仅通过机器人间接影响可达性——停用 / 删除地图后该图覆盖点位「暂无机器人可达」，坐标与数据不失效。

原型尚未跟进：`Point` 仍保留 `mapId` 字段，且多处仍把它当作「点位归属哪张图」直接判定。本次待办的目标是把归属改为**运行时计算**，最后删掉字段。

## 2. 现状

地图删除 / 重传后巡检点仍可用，绑定关系以 targetId → Candidate 为准，
权威坐标以统一坐标系 world 为准，不以本字段判别身份。

## 3. 甄别规则（实施前必读）

**只清 `Point.mapId`，其余 `mapId` 一律保留**，别一把梭：

| 字段 | 含义 | 处理 |
|---|---|---|
| `Point.mapId` | 点位归属地图 | **删除** |
| `Robot.mapId` | 机器人当前地图 | 保留，这是「间接关系」的载体 |
| `Task.mapId` | 任务快照地图 | 保留 |
| `Route.mapId` / `Template.mapId` | 路线在地图侧视图的图层归属 | 保留 |
| `TrackSample.mapId` / `SiteSurvey.mapId` | 录制轨迹与踩点记录 | 保留 |
| `Sync.mapId` / `Change.mapId` / `RailSection.mapId` | 下发记录 / 变更登记 / 轨道分段 | 保留 |
| `IF-07` 接口 `mapId` | 地图下发入参 | 保留 |

## 4. 三步走

### Step 1：新增 `mapIdOf()` 选择器

- 位置：`src/data/selectors.ts`（或新建 `src/data/pointMap.ts`）
- 签名：`mapIdOf(point: Point, maps: Map[]): string | null`
- 算法：复用路线侧已有的「点在多边形内」（Point-In-Polygon），输入点位 `world` 坐标，返回命中的地图 id
- 兜底：命中 0 张 → 返回 `null`；命中多张（图重叠）→ 取**已启用且版本最新**的一张，其余忽略
- 性能：结果按 `pointId` 做 memo，避免 200+ 处调用重复计算
- 单测 3 条：图内命中 / 图外返回 null / 两图重叠时的取舍

### Step 2：逐页替换

按依赖顺序替换，每换完一层跑一次 `npx tsc --noEmit`：

1. **数据层**：`selectors.ts` → `engine.ts`（派单校验、地图覆盖判定）→ `mapCalibration.ts`
2. **页面层**：`Maps.tsx` → `SpaceManage.tsx` → `MapCalibrate.tsx` / `MapSurveyPanel.tsx` / `MapOnboarding.tsx` / `MapDispatch.tsx` / `MapBindPicker.tsx` / `MapBaseUpload.tsx` / `MapNavigate.tsx` / `MapDetail.tsx` / `PointCalibration.tsx` / `RoutePreview.tsx` / `OnsiteSetupModal.tsx` / `QuickTaskDrawer.tsx`
3. **外围**：`Planning.tsx` / `Results.tsx` / `Metrics.tsx` / `metrics.ts` / `Execution.tsx` / `Operations.tsx` / `OperationsLegacy.tsx` / `Supporting.tsx`

替换时 `p.mapId === mapId` 统一改写为 `mapIdOf(p, s.maps) === mapId`；`p.mapId` 作为展示文案的地方改成 `mapIdOf(...) ?? "未归属"`。

### Step 3：删字段

- `types.ts` 删除 `Point.mapId`（连同注释）
- `seed.ts` 删除所有点位的 `mapId` 赋值（36 处）
- `excel.ts` 巡检点导入映射去掉地图列
- 全量 `npx tsc --noEmit` + `npm test`，此时编译报错会精确指出所有残留引用

## 5. 兜底策略（点位落在所有地图外）

| 场景 | 处理 |
|---|---|
| `mapIdOf()` 返回 `null` | 点位标「未归属地图」，列表加「未归属」筛选，行内给「重新标定」入口 |
| 派单校验「地图覆盖」 | 直接拦截：「点位坐标不在任何地图覆盖范围内，请先建图或重新标定」 |
| 路线 / 计划引用该点位 | 允许引用（点位数据有效），执行时由校验拦截，不静默跳过 |
| 地图删除后点位 | 仍可编辑，仅显示「暂无机器人可达」 |
| 演示种子数据 | 实施时用脚本跑一遍，列出落在地图外的点位，补坐标或补地图边界 |

## 7. 验收清单

1. 点位落在某图内 → 列表显示该图名称，派单校验通过
2. 点位落在所有图外 → 标「未归属地图」，派单被拦截并给出重新标定入口
3. 两张图边界重叠 → `mapIdOf()` 稳定返回同一张（已启用 + 最新版本），重复调用结果一致
4. 停用地图 → 该图覆盖的点位显示「暂无机器人可达」，点位本身仍可编辑
5. 删除地图 → 点位数据不变，`mapIdOf()` 返回 `null`，点位转「未归属」
6. 地图重新建图并启用 → 原先「未归属」的点位自动恢复归属（无需人工改数据）
7. 跨图任务（点位分散在两张图）→ 派单拦截，提示「已选点位分散在 N 张地图的覆盖范围内」
8. 点位详情、路线预览、标注工作台的地图定位与改造前一致
9. `Point` 类型删掉 `mapId` 后 `tsc` 无报错，`npm test` 无新增失败
10. 演示数据全量跑一遍，没有「未归属」的意外点位（除刻意保留的样例）

## 8. 风险

| 风险 | 应对 |
|---|---|
| 演示数据里有边界外点位，改造后突然「未归属」，演示效果变差 | Step 3 之前先跑脚本体检，补地图边界或挪坐标 |
| 图重叠导致归属抖动 | `mapIdOf()` 内固定取舍规则，不依赖数组顺序 |
| 200+ 处调用带来卡顿 | 按 `pointId` memo，地图启用 / 删除时失效缓存 |
| 测试大量依赖 `mapId` 构造数据 | 先抽 `makePoint({ mapId })` 之类的构造器，删字段时只改构造器 |
